# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `POST /attendance/punch-in` | Concurrency race condition: used check-then-insert (`find_one` then `insert_one`) without relying on database-level constraints. | Parallel identical punch-in requests created duplicate daily records for the same employee or threw unhandled 500 errors. | Created a compound unique index on `(emp_code, date)` and handled `DuplicateKeyError` directly, returning 409 Conflict. |
| 2 | `compute_late_minutes` | Subtracted grace period from late minutes (`diff - 10`) and used non-strict inequality (`>= 10`), violating Rule R2. | Shift 09:30 punched in at 09:40:00 returned late (should be 0); punched in at 09:45:00 returned 5 minutes instead of 15. | Checked `diff_seconds > 600` (strictly > 10 min); when true, calculated `diff_seconds // 60` from `shift_start` (not grace end); else 0. |
| 3 | `determine_attendance_date` | Did not account for IST timezone (UTC+05:30) or overnight shifts (`shift_end <= shift_start`), using naive local dates. | An overnight shift (22:00-06:00) punching in at 01:00 AM on July 7 was wrongly logged as 2026-07-07 instead of 2026-07-06. | Converted UTC instants to IST, checked if `shift_end <= shift_start` and current IST time `< shift_end`, attributing date to previous day. |
| 4 | `compute_work_hours` / `compute_attendance_pct` | Used Python's built-in `round()` which performs round-half-to-even (banker's rounding) and suffers floating-point inaccuracies. | Values ending in exact half-fractions (e.g. 2.125) rounded down to 2.12 instead of 2.13, failing contract Rule R4/R8. | Implemented `round_half_up` utilizing Python's `decimal.Decimal` with explicit `ROUND_HALF_UP` quantization. |
| 5 | `GET /attendance` | In-memory pagination: loaded entire collection into Python memory via `list(cursor)` and sliced `[skip:skip+limit]`. | High memory consumption and severe latency degradation (>2s) on 100k records; explain showed COLLSCAN. | Used native MongoDB `.skip(skip).limit(page_size)`, `count_documents(q)`, backed by composite index `{"date": -1, "emp_code": 1}`. |
| 6 | `validate_epoch_ms` | Timestamp validation was missing or allowed non-millisecond values, floats, and strings without proper rejection. | Sending a 10-digit Unix timestamp (seconds, e.g. 1783312500) was accepted and created dates in 1970 instead of HTTP 422. | Enforced integer type checking and range boundaries `[100000000000, 4102444800000]`, raising HTTP 422 on invalid inputs. |
| 7 | `truncate_to_seconds` | Sub-second milliseconds were preserved rather than truncated before calculations, violating Rule R1. | Input timestamp `1783312500850` preserved fractional milliseconds, causing rounding drifts in work durations. | Implemented explicit integer truncation `(ms // 1000) * 1000` at API boundary upon ingestion. |
| 8 | Document Serializers | Internal MongoDB `_id` was exposed directly in serialized API response dictionaries. | Response JSON contained `_id: "..."` or raised `TypeError: ObjectId is not JSON serializable`, violating API contract. | Popped `_id` (and any alias `id`) from response payloads in `serialize_employee` and `serialize_attendance_record`. |
| 9 | `GET /health` | Health endpoint returned a static hardcoded `{"status": "ok"}` without verifying database connectivity. | Endpoint returned HTTP 200 even when MongoDB daemon was stopped or network connection dropped. | Added `db.command("ping")` within try/except block; returned HTTP 503 if database fails to respond. |
| 10 | `POST /employees` | Concurrency race condition: duplicate check performed in application logic without unique index enforcement. | Simultaneous creation requests with identical `emp_code` both returned 201 Created, causing corrupted directory state. | Created unique index on `{"emp_code": 1}` at startup; caught `DuplicateKeyError` to return HTTP 409 Conflict. |
| 11 | `POST /employees` | Allowed identical `shift_start` and `shift_end`, creating an impossible 0-duration / ambiguous shift definition. | POST request with `shift_start: "09:00"` and `shift_end: "09:00"` returned 201 Created instead of 422. | Added Pydantic model validator verifying `shift_start != shift_end`, automatically failing with HTTP 422. |
| 12 | `serialize_attendance_record` | Missing field crashes on legacy attendance documents (e.g. documents without `history`, `late_minutes`, or `half_day`). | Querying seeded legacy documents raised `KeyError` and crashed with HTTP 500. | Provided robust defaults (`half_day: False`, `history: []`, `late_minutes: 0`, `overtime_minutes: 0`) during serialization. |

### Examined and Decided NOT a Defect

1. **Absence of User Authentication / Authorization**: The problem statement explicitly states that the assignment focuses on data modeling, rules, and MongoDB aggregation performance; user authentication is intentionally omitted for this scope.
2. **PyMongo Returning Naive Datetimes**: By default, PyMongo returns naive datetimes. Configuring `tz_aware=True` on `MongoClient` and treating all stored BSON dates as UTC ensures consistent instant conversions to epoch milliseconds without modifying the database driver architecture.
3. **Omitting `_id` on Attendance Records**: Addressing attendance documents by `(emp_code, date)` rather than an ObjectId is an intentional business design pattern specified in the contract; having no surrogate key on attendance logs is not a defect.
